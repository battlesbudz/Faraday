## Selected hardening

The selected defect is the M5 model-identity omission. The shared conversation mode design increases the importance of a single process resident being bound to the selected model. `ConversationModelSession.prepare()` now snapshots the selected spec and closes/clears a resident whose `modelId` differs before mode checks or backend return. Existing close ordering still runs through the native mutation fence and checked native lifecycle.

The captured MCP fixture follow-on was not selected because the model identity issue is a correctness defect in the active shared-engine path. Fixture provenance also prohibits inventing missing server captures; only existing authentic captures should be expanded into additional replay coverage.
